# Trust, evidence, and limits

Agent Swarm Orchestration coordinates cognition; it does not turn a role label into competence, worker agreement into truth, tool access into permission, or simulated stakeholders into stakeholder authority. Version 0.3.1 retains that promise with repaired execution and packaging checks. Exact runtime membership and fingerprint come from the delivered package custody manifest; historical receipts stay historical.

## Keep one authority envelope

Delegation transfers bounded work custody. It does not expand what the user authorized. The root may delegate only reads, writes, tools, network use, and external actions already admitted for the mission. Publication, deployment, purchases, account changes, credentials, destructive operations, permission changes, stakeholder representation, and risk acceptance remain separate authority edges.

An authority edge blocks only the action beyond it. The root should continue authorized investigation, analysis, comparison, private preparation, and reporting while reserving the ungranted action.

## Design contributions, not costumes

A persona or role name may make a stance memorable, preserve a perspective, or perturb search. It does not establish that the contribution is useful, independent, competent, or legitimate. Each admitted member needs a causal job: a distinct transformation, evidence channel, capability, error opportunity, containment boundary, check, or justified redundancy, plus a named consumer.

Organizational analogies are mechanism libraries. Bucketlines, anthills, platoons, boardrooms, general staffs, complex adaptive systems, and unfamiliar hybrids can all be useful; none is a universal template. The coordinator should compare the proposed form with a strong direct route and the nearest simpler organization, then reform or dissolve it when evidence changes the live problem.

An agent may analyze testimony, policy, survey data, meeting records, or competing stakeholder claims. It is not thereby authorized to speak *as* residents, employees, customers, experts, or any other affected group. Evidence about a constituency and standing to represent it are different things.

## Treat returns as reports

Use these states consistently:

| State | Meaning |
|---|---|
| **Assigned** | A member received responsibility. |
| **Dispatched** | The host accepted creation or a turn trigger. |
| **Agent-reported** | A member claimed a result. |
| **Observed** | The root inspected the named source, artifact, output, status, or external state. |
| **Reconciled** | Intended state and authoritative post-state were compared. |
| **Independently verified** | A separate credible check supported the exact predicate. |

Completion of a worker turn does not establish factual truth, successful mutation, rollback, or mission completion. Agreement after shared anchoring is not independent corroboration. Preserve stronger minority evidence and unresolved value conflict rather than letting a vote impersonate a resolver.

## Protect state and private material

Give each member only the context needed for its contribution. Do not copy secrets, personal data, private corpora, or unrelated repository content merely because another context exists. Treat packets, messages, returns, and shared artifacts according to the live host's retention and security policy; this package does not create an encrypted channel or separate privacy boundary.

Keep one writer per mutable surface at a time. Parallel readers may inspect the same evidence. Sequential writers must begin from observed, reconciled current state. Interruption is not rollback evidence; uncertain writes and external actions require authoritative readback.

The organization should distinguish task truth, accepted progress, evidence, scratch reasoning, and artifact state. At a phase change, state what is retained, superseded, invalidated, discarded, or re-derived.

## Read the live host contract

Collaboration controls are host-provided and volatile. The skill must inspect live tool presence, schemas, concurrency, context forks, model routes, messages, waits, interruption, cancellation, nested delegation, and lifecycle semantics before relying on them. Documentation examples describe intent; they do not freeze a future host API.

## What the current local checks establish

The local release gate can establish that:

- canonical, plugin, standalone Codex, and standalone Claude runtime trees are byte-identical;
- the manifest lists the actual canonical runtime files and matches their exact bytes;
- the Swarm Plan validator's structural tests pass;
- vNext eval manifests, schemas, fixtures, IDs, hashes, and declared evidence contracts are internally valid;
- historical source-level scenarios remain preserved; this repair adds executable admission and lifecycle counterexamples plus expert task contrasts, with zero new model trials;
- the plugin and standalone ZIPs reproduce their governed source trees under one safe POSIX top-level folder;
- archive custody, detached checksums, the selected skill-ZIP sidecar, and its verification instructions agree with actual bytes;
- customer documentation files, navigation, local links, accessibility structure, visual dimensions, and archive references pass the repository's static checks;
- the frozen post-tag v0.2.3 baseline bytes remain unchanged.

These are exact local predicates. They do not establish public availability or live host behavior.

## Evidence that does not transfer

The older 0.1.0 runtime had bounded Codex decision qualification, including one isolated natural trial per case. Version 0.2.3 packaged that earlier runtime. Version 0.3.0 changes the runtime fingerprint and does not borrow those behavioral results as if the prompt were unchanged.

The v0.2.3 Git tag and the later reconciled v0.2.3 baseline bytes are also distinct custody facts. Version 0.3.0 preserves the tag, later baseline archives, checksums, and receipts without moving the tag or rewriting history.

The 0.3.0 vNext live-control cases and role-synergy ablations remain **specified, not run**. Their existence is an evaluation contract, not evidence that adaptive organizations execute reliably or outperform a strong direct agent.

## What remains unestablished

The current runtime does not by local packaging alone establish clean-host installation, discovery, implicit routing, invocation, live collaboration-tool execution, Claude activation, repeatability across models, universal reliability, universal cost or latency savings, superiority of any role composition, stakeholder legitimacy, customer productivity, customer outcomes, background execution after the task ends, rollback after interruption, assistive-technology conformance, directory approval, public repository state, a GitHub release, or Pages deployment.

A passing Swarm Plan validates declared structure, not synergy, competence, factual correctness, or organizational value. A matching ZIP hash proves byte identity, not installation or healthy behavior. Publication, installation, discovery, invocation, and behavior require separate observations.

## Human control and safe stopping

The user retains purpose, priorities, values, risk acceptance, new authority, sensitive disclosure, stakeholder standing, installation, and publication. The root owns integration only inside the authorized mission.

When evidence, authority, tools, cost, or quality cannot support another responsible in-bounds step, stop with the strongest useful result and an exact boundary such as `RETURNED — NOT RECONCILED`, `PARTIAL — DEPENDENCY UNAVAILABLE`, `AWAITING AUTHORITY`, or `CAPABILITY-LIMITED`. The temporary organization exists to finish the mission. It is not a tiny constitutional crisis that has learned JSON.

## Distribution boundary

A local candidate establishes only its observed checks. Installation, fresh-host discovery, invocation and public publication have their own evidence. Existing authorization follows its actual scope; this document creates no additional permission gate. Earlier public or installation evidence is not borrowed for changed bytes.
## Read the plan verdict precisely

The validator reports declared control and mission outcome separately. Missing outcome is unverified; accepted requires passing coverage of the stated criteria and no unresolved writes. It checks declarations and evidence references, not their authenticity or truth. Follow [Plan validation and recovery](PLAN-VALIDATION.md) for the exact field meanings and examples.
