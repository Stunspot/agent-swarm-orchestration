Orientation

Use a swarm when divided cognition improves the accepted result—not because agent slots happen to exist.

Built for

People using an AI host that can create or coordinate agents and who need explicit mission custody, bounded delegation, single-writer ownership, evidence reconciliation, and recoverable closure.

Best-fit work

Independent repository or document review, competing hypotheses, staged specialist handoffs, read-only parallel inspection, independent challenge, and recovery from stale or conflicting agent work.

What it does

Chooses Direct, Enlist, Assemble, Chain, or Recover; composes bounded worker packets; protects mutable surfaces; tracks evidence states; and integrates one accountable answer.

What it cannot do

It does not create missing agent tools, enlarge authority, prove worker claims, guarantee savings, roll back uncertain writes, or continue after the host task ends.

The five operating shapes

Admit the lightest topology that can improve the outcome.

  1. 01
    Direct

    Keep small, sequential, tightly coupled, latency-sensitive, or shared-surface work with the root.

  2. 02
    Enlist

    Give one bounded worker one useful slice while the root continues the mission.

  3. 03
    Assemble

    Run independent, ready slices concurrently under separate ownership and a named merge question.

  4. 04
    Chain

    Accept one specialist’s result before using it as the next specialist’s exact input.

  5. 05
    Recover

    Preserve accepted work, change the failed premise, and resume from the first unearned edge.

Verification path

Confirm discovery before judging orchestration.

  1. Start a fresh host task after installation or reload.
  2. Invoke the exact skill name: $agent-swarm-orchestration.
  3. Use a task with genuinely independent read surfaces.
  4. Confirm the host recognizes the skill and selects a named topology.
  5. If agents are warranted, confirm the current task exposes usable collaboration controls.
  6. Accept success only when the root returns one evidence-bounded result. A justified Direct decision also counts.

First successful use

Begin with independent evidence questions and read-only authority.

Use $agent-swarm-orchestration to inspect billing, search, and notifications for retry behavior. Keep every worker read-only. Decide whether parallel agents earn their coordination cost, give each worker one bounded evidence question, and return one comparison with the riskiest inconsistency. Treat worker findings as reported until you inspect their cited evidence.

Input

A desired outcome, acceptance condition, available evidence, authority, constraints, and a task whose dependencies can be distinguished.

Output

One integrated answer that names the selected topology, reconciled evidence, unresolved conflict, limits, worker disposition, and any exact re-entry condition.

Representative workflows

Coordinate the dependency shape that is actually present.

Parallel inspection

Assign independent repositories, folders, datasets, or hypotheses to read-only workers. Keep the cross-area comparison and evidence acceptance with the root.

Dependent specialists

Use a Chain when the second specialist cannot begin until the root has inspected and accepted the first result.

One shared file

Collect independent comments if useful, but preserve one writer at a time. Correctness-bearing changes precede clarity and polish.

Competing explanations

Use fresh contexts to reduce shared anchoring, then choose among claims through evidence or the cheapest discriminating check—not confidence or consensus.

Troubleshooting and maintenance

Preserve evidence before reset, and classify the real boundary.

Skill not recognized

Check folder topology or plugin registration, start a fresh task, and invoke the exact name. Existing files do not prove discovery.

No agents created

This may be correct. Confirm the topology decision and whether the current task exposes collaboration controls before treating Direct as failure.

Workers conflict

Compare source scope, time, version, assumptions, and artifacts. Keep returned claims agent-reported until the root inspects evidence.

Write state uncertain

Read authoritative post-state before retrying. Interruption is not proof of rollback, non-commit, or unchanged state.

UpdateBack up the installed folder, replace the complete package, reload if needed, then repeat discovery and first-invocation checks.
RemoveRemove only the exact plugin or skill folder, reload discovery, and confirm absence. Running agents and external actions require separate reconciliation.
Clean upThe Augment creates no account or database. Delete only user-created plans, ledgers, packets, or outputs you no longer need, subject to host retention.

Privacy, storage, network, and security

The package is local; the host and tools define the surrounding data boundary.

Package behavior

No account, telemetry, analytics, connector, MCP server, hosted service, hook, or automatic network request is included.

Storage

The package has no database or automatic persistence. Plans, ledgers, packets, logs, and outputs exist only where the user or host creates and retains them.

Delegated context

Send each worker only the smallest necessary source material. Host, model, repository, and connector retention policies still apply.

Authority

Tool access does not grant permission. Publication, deployment, purchases, credentials, destructive work, and sensitive disclosure remain explicit authority edges.
