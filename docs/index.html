Agent Swarm Orchestration decides whether a task will actually benefit from multiple AI agents. When the answer is yes, it divides independent work, prevents overlapping writes, checks worker returns against evidence, and assembles one coherent result. When the answer is no, it keeps the work with one agent and saves you a tiny bureaucracy with tokens.

What it does

More agents help only when the work divides cleanly.

ASO gives the coordinating agent five moves: work directly, enlist one specialist, assemble independent workers, chain dependent specialists, or recover a failed swarm. The coordinator must justify the shape, bound every job, preserve your authority, and own the final answer.

The mission stays at the root

Workers get a job, not the steering wheel. Your outcome, constraints, corrections, and reserved decisions remain with one coordinator.

One writer owns each surface

Agents may inspect the same evidence in parallel. They do not edit the same file or external object at the same time and call the collision collaboration.

A worker report is not yet a fact

The root inspects cited files, sources, command results, or live state before promoting a return into the final answer.

ASO does not manufacture agent tools. It uses the collaboration controls exposed by the current AI host. No controls means no dispatched swarm—and no fiction that one ran.

The five operating shapes

Use the smallest topology that earns itself.

  1. 01
    Direct

    Keep small, sequential, shared-context, or same-surface work with the root.

  2. 02
    Enlist

    Give one bounded specialist one useful slice while the root continues.

  3. 03
    Assemble

    Run independent ready work concurrently with separate ownership and a named merge.

  4. 04
    Chain

    Accept one specialist's result before using it as the next specialist's exact input.

  5. 05
    Recover

    Keep accepted work, change the failed premise, and resume from the first unearned edge.

What a good run returns

  • A justified choice: Direct, Enlist, Assemble, Chain, or Recover.
  • One bounded responsibility for every worker.
  • Clear separation between worker reports and root-observed evidence.
  • One reconciled conclusion, unresolved conflict, or truthful degraded state.

Success is not “three agents answered.” Success is a better accepted result after startup, duplicated reading, coordination, merge, verification, latency, and token cost. Sometimes the winning swarm has one member. Physics remains stubbornly unimpressed by org charts.

Compare independent components

Send read-only workers into separate systems, then keep the cross-system risk judgment with the root.

Sequence dependent experts

Identify and verify the owning component first. Only then dispatch the specialist whose work depends on that answer.

Challenge a finished artifact

Give a fresh reviewer the target and evidence without leaking the builder's preferred verdict.

What it prevents

Coordination theatre is still theatre, even with excellent tool calls.

  • spawning workers because slots exist;
  • parallel writers colliding on one file;
  • dependent work disguised as concurrency;
  • private context copied wholesale into every packet;
  • agent confidence promoted into observed fact;
  • interruption described as rollback;
  • cheap token prices described as accepted-outcome savings.

Troubleshoot and recover

Fix the failed edge—not the entire universe.

The skill is not listed

Check the exact folder shape or plugin registration, refresh the host, and resolve the skill by name in a new task.

No agent controls exist

The package cannot create them. Work directly or return an exact delegation packet marked PREPARED — NOT DISPATCHED.

A worker failed

Keep accepted work and the failure signature. Change the packet, source, route, model, tool, owner, or sequence before retrying the unfinished slice.

A write may have landed

Read the authoritative file or external state before another mutation. Interruption does not prove rollback.

Updating means replacing or upgrading the package, refreshing the host, and repeating discovery plus invocation checks. Removing the skill does not cancel workers, undo commits, reverse deployments, or delete plans and logs you saved elsewhere.

Privacy, security, and evidence

Know what stays local—and what the tests actually prove.

The package itself has no account or telemetry

Its skill files and optional Python validator make no automatic network request. Your AI host, model provider, repository service, and chosen tools remain separate data and network boundaries.

Validation is deliberately bounded

The retained tests cover package parity, plan structure, and ten Codex decision cases. They do not prove every model, live host, tool contract, customer outcome, accessibility configuration, or cost claim.

Minimize private context in every worker packet. Tool access never enlarges authority. If a write or external action is uncertain, inspect the destination instead of letting a confident sentence impersonate a receipt.
