The promise

A swarm should multiply useful cognition—not divide responsibility until nobody owns the truth.

It is for people using an AI host that can create or coordinate agents. It solves the governance problem around delegation: when to split work, what each worker owns, what authority travels with a packet, how returns become evidence, and how the root recovers from a failed route.

Mission custody

One root holds the desired outcome, authority envelope, budgets, user corrections, and final answer.

Surface ownership

Workers receive coherent responsibilities. Every mutable surface has one writer at a time.

Evidence custody

Worker returns remain agent-reported until the root inspects the cited source, artifact, or receipt.

It does not spawn agents by itself. The package supplies decision doctrine, templates, a plan schema, and an optional validator. Agent controls, files, browsers, networks, credentials, and external actions come from the live host and remain inside the user's authority.

The five operating shapes

Use the smallest topology that improves the accepted result.

  1. 01
    Direct

    Keep small, sequential, tightly coupled, or shared-surface work with the root.

  2. 02
    Enlist

    Give one bounded worker one useful slice while the root continues the mission.

  3. 03
    Assemble

    Run independent, ready slices concurrently under explicit ownership and a named merge plan.

  4. 04
    Chain

    Accept one specialist's result before using it as the next specialist's exact input.

  5. 05
    Recover

    Preserve accepted work, change the failed premise, and resume from the first unearned edge.

Expected output shape

  • An admitted topology: Direct, Enlist, Assemble, Chain, or Recover.
  • Bounded responsibilities with explicit read, write, and authority limits.
  • Agent-reported returns kept separate from root-observed evidence.
  • One reconciled conclusion, unresolved conflict, or truthful degraded state.

Success is not "three agents answered." Success is that the accepted result is better after startup, duplicated reading, coordination, merge, verification, latency, and token cost. A Direct answer is correct when a swarm does not earn itself.

Independent comparison

Assemble read-only workers for separate components; keep the cross-component risk judgment with the root.

Sequential specialist chain

Identify and validate a dependency first; dispatch downstream design only after its accepted return exists.

Hostile review

Use fresh context for an independent challenge and withhold the builder's preferred verdict or hidden rubric.

What it prevents

Coordination theatre is still theatre, even with excellent tool calls.

  • spawning workers because slots exist;
  • parallel writers colliding on one file;
  • dependent work disguised as concurrency;
  • private context copied wholesale into every packet;
  • agent confidence promoted into observed fact;
  • interruption described as rollback;
  • cheap token prices described as accepted-outcome savings.

Configuration, troubleshooting, and recovery

Most failures are boundary failures, not invitations to invent another swarm.

No package configuration file

The skill has no account, API key, service endpoint, telemetry switch, or background worker. It reads the live host's injected controls. Python 3 is needed only for the optional plan validator.

Skill not discoverable

Confirm the exact extracted folder, plugin registration, enabled state, and fresh-task resolution. Do not call a copied folder installed until the host lists it.

No collaboration controls

Finish root-owned work and return a precise prepared packet or plan labelled PREPARED - NOT DISPATCHED. Do not claim workers ran.

Worker or merge failure

Preserve useful evidence, classify the failure, reconcile authoritative current state, and change the faulty packet, dependency, tool, model, owner, or sequence before retrying.

To update, compare versions, read the release notes, back up local modifications, replace or upgrade the package, restart the host, and repeat discovery plus invocation checks. To remove, delete the standalone folder or use the host's plugin removal command. Remove any exported plans, ledgers, logs, or local copies separately if you created them.

Privacy, security, and evidence

Local package, host-governed data, bounded validation.

Privacy and storage

The package sends no telemetry and operates no hosted service. Your host may retain prompts, packets, messages, returns, files, logs, and outputs under its own policy. The package supplies no separate deletion mechanism.

Network and authority

The package makes no automatic network request. Workers may use only host tools and actions already authorized by the user. Tool access never widens permission.

Security boundary

Minimize private context, keep one writer per mutable surface, reconcile post-state after interruption, and treat agent output as untrusted until observed.
